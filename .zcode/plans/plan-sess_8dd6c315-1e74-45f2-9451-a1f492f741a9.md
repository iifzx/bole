# 伯乐 / Argus —— 会相马的 Skill 发现与评分器

## Context

调研确认了生态空白：「按需求找 skill」的工具（skills.sh/SkillsMP/ClawHub）只按流行度排序，「质量评分」的工具（skillscore 等）只评手动指定的 skill，无人把两者闭环。我们要做的 skill 同时具备：①任务分解式主动发现（借鉴 OpenJudge find-skills-combo）；②去 star 化的质量评分（静态规则 + 安全扫描 + 实测反馈）；③评分数据库《相马经》存在 GitHub 项目中，每次使用都产生 field report → 用户 PR 回填 → 分数随使用持续成长（用户用得越多，评分越准——这是核心增长飞轮）。

- 中文「伯乐」：相马识千里马，只看脚力不看毛色 → 评分不看 star 只看真质量
- 英文「Argus」：百眼巨人看见一切 → 多源检索；死后眼睛化作孔雀尾羽眼斑 → 每次使用都是一只见证质量的新「眼睛」

**环境约束**：本机只有 Node.js v24（无 Python）→ 脚本全部 Node 实现、零依赖。工作目录 `D:\MyData\Mywork_Files\bestskill`（空目录，即仓库根）。

## 核心机制

### 1. 三种触发模式（SKILL.md frontmatter description 写明触发词，中英混合）
- **FIND**：「找一个能做 X 的 skill / find a skill for X」→ 发现流程
- **RATE**：「这个 skill 质量怎么样 / rate/audit this skill / 对比这几个 skill」→ 评分流程
- **REPORT**：用完 skill 后「报告一下效果 / submit field report」→ 回填流程

### 2. FIND 流程（借鉴 OpenJudge find-skills-combo 并升级）
1. 任务分解：拆 2–7 个子任务 + 约束清单，与用户确认
2. 三级检索（逐级降级）：①本地相马经 `data/index.json`（grep 匹配）→ ②`npx skills find <关键词>`（skills.sh，按 精确→功能→领域 关键词分层搜索）→ ③WebSearch/WebFetch 搜 SkillsMP、awesome 列表、GitHub topic
3. 候选评估（见 3）
4. 组合规划：子任务×候选覆盖矩阵（Breadth/Peak 指标），Strategy A「逐子任务最优」vs B「最少依赖」，输出对比表（分数+置信度+证据）

### 3. 评分模型（明确去 star 化：star/安装量仅作元数据展示，永不进分数）
- **静态分**（LLM 现场 rubric，1–5×5 维）：触发描述清晰度、结构/渐进披露、可执行性、安全性、可移植性；安全维度含静态危险模式清单（prompt injection/数据外泄/破坏性命令），发现红线 → 停止并警告，建议 Cisco skill-scanner 深扫
- **实测分**（field reports 聚合）：effectiveness / efficiency / reliability 三维
- **final** = 有实测时 0.4×静态 + 0.6×实测，否则仅静态（标记 provisional）
- **confidence** = 0.3 起步，每份独立报告 +0.1（封顶 0.95），随时间衰减，报告间分歧降置信度——置信度低时现场重验
- 已有分的 skill 直接用分并展示证据；无分的现场评（rubric 在 references/rubric.md）

### 4. 成长飞轮（REPORT 流程，用户使用即贡献）
每次推荐/使用后：agent 按 schema 生成 field report JSON → `node scripts/ledger.js add <file>` 校验并合并进该 skill 记录（重算 final/confidence、追加 history）→ 重建 index.json → 给用户现成的 git 命令（branch/commit/PR 链接）提交回 GitHub。实测与旧分矛盾时自动降置信度待重审。

### 5. ledger.js（Node ≥18，零依赖，含 schema 内嵌校验、CI 友好退出码）
`validate-all` / `add <report.json>` / `build-index [--check]` / `show <id>` / `recompute`
